# B.11 Los Blocks de pantalla se generan como páginas del usuario

[← Índice del plan](../../plan.md)

- [~] B.11 `ng g mimi login-01` deja de generar un componente «mimi-login-01» y crea una página del usuario (`src/app/pages/login/`, clase `LoginPage`, con su archivo de rutas).
  - Sin versión (sale en la siguiente que se publique; el CHANGELOG la lleva en «Por publicar») · Tamaño L (CLI, registro, showcase y escenarios con el `.tgz`) · Depende de: B.P (hecha; la 0.4.0, publicada el 07/11/2026) · Bloquea: B.9 (`table-01` tendrá que declarar si es página o sección)
  - Estado: en curso en `auto/blocks-paginas-2026-11-07` (Claude Code, modo autónomo), desde el 07/11/2026.
  - Leer antes: spec 4, «Blocks»; spec 5, «Qué hace `mimi`» (pasos 3 a 9: todo o nada, bases, `mimi.json`), «Aviso de un componente que usa un Block (M1)», «`@source` de los Blocks con `source(none)` (G1)», «`mimi.json`» y «Alias válidos (M2)»; `docs/historial/blocks/B.1.md` (la arquitectura del tipo `block`); `docs/auto/revision-blocks-0.4.0-2026-11-07.md` (M1, M2, G1).
  - Diseño: no aplica (es la CLI; las pantallas no cambian). La página de Blocks del sitio se arma con lo que ya tiene (D6).
  - Objetivo: que un Block que es una pantalla entera quede en el proyecto como una página propia del usuario, con nombre de página y su ruta lista para pegar, y que los que son una parte de una página sigan copiándose como ahora.
  - Alcance:
    - Incluye: la marca `page` / `section` de cada Block en el registro; el alias `aliases.pages`; el nombre por defecto y `--name`; la clase y el selector sin `mimi`; el archivo `<nombre>.routes.ts` y la línea para `app.routes.ts`; el seguimiento por el nombre del registro (bases, manifiesto, `mimi.json`); la compatibilidad con los Blocks instalados con la 0.4.0; M2 para `aliases.pages`; el `@source` de la carpeta de páginas con `source(none)`; la página de Blocks del sitio, la de Instalación (el `mimi.json` de ejemplo con `aliases.blocks` y `aliases.pages`), el README de la CLI, la spec y el CHANGELOG («Por publicar»).
    - NO incluye: editar `app.routes.ts` del usuario (solo se imprime la línea); dependencias nuevas; cambiar el código de las pantallas en ui-core (el showcase sigue usando `Login01`); subir la versión o publicar; `mimi update` (5.4).
  - Base técnica: ninguna de aria ni cdk. Angular Schematics, como el resto de la CLI.
  - Decisiones (las da el prompt de la sesión; adoptadas por defecto el 07/11/2026, pendientes de revisión del usuario; filas en `docs/auto/decisiones-por-defecto.md`):
    - **B.11-a** El registro marca cada Block con `kind: "page"` o `kind: "section"`. Páginas: `login-01`, `login-02`, `signup-01`, `otp-01` y `settings-01` (pantallas enteras que van solas en una ruta). Sección: `pricing-01` (la tabla de planes va dentro de una página de precios o de la landing, junto a otras partes). `registry.spec.ts` exige la marca en todos los Blocks.
    - **B.11-b** Las páginas van a `aliases.pages` (nuevo), por defecto la carpeta hermana de `components/` como los Blocks (`src/app/components/ui` → `src/app/pages`). `init` lo escribe; en un proyecto anterior, `ng g mimi` lo escribe la primera vez que copia una página. Las secciones siguen en `aliases.blocks`.
    - **B.11-c** Nombre por defecto: el del registro sin el número (`login-01` y `login-02` → `login`, `signup-01` → `signup`, `otp-01` → `otp`, `settings-01` → `settings`). `--name <kebab-case>` lo cambia (solo con una página en el comando). Si la carpeta `<aliases.pages>/<nombre>/` ya existe y no es esa misma página, falla antes de escribir nada y pide `--name`; nunca la sobrescribe (tampoco con `--overwrite`).
    - **B.11-d** Archivos `<nombre>.ts` y `<nombre>.html` (sin `index.ts`); clase `<Nombre>Page` (`LoginPage`) y selector `<prefijo>-<nombre>-page` (`app-login-page`), con el prefijo del proyecto en `angular.json` (o `app`). Los tipos del Block se renombran igual (`Login01Value` → `LoginPageValue`).
    - **B.11-e** `<nombre>.routes.ts` exporta `LOGIN_ROUTES` con la página en carga diferida (`loadComponent`); el resumen imprime la línea exacta para `app.routes.ts` (`{ path: 'login', loadChildren: () => import('./pages/login/login.routes').then((m) => m.LOGIN_ROUTES) },`). No se edita `app.routes.ts`. `@angular/router` no se declara: lo trae toda app de Angular.
    - **B.11-f** Seguimiento por el nombre del registro: las bases van a `.mimi/base/pages/<nombre del registro>/` y el manifiesto usa esas claves (`pages/login-01/login-01.ts`); `mimi.json → blocks.login-01` guarda además dónde está (`"path": "src/app/pages/login", "name": "login"`). El todo o nada, los avisos de M1 y `--overwrite` funcionan igual aunque el usuario elija otro nombre; si mueve la carpeta, cambia `path` en `mimi.json`.
    - **B.11-g** Compatibilidad con la 0.4.0: una pantalla instalada con la 0.4.0 (`<aliases.blocks>/login-01/login-01.ts` y su entrada de `mimi.json` sin `path`) se queda donde está y se sigue actualizando ahí, como en la 0.4.0 (`Login01`, `mimi-login-01`). Para pasarla a página: guardar los cambios, borrar su carpeta y volver a ejecutar `ng g mimi login-01`.
    - **B.11-h** **RUPTURA:** en un proyecto sin la pantalla instalada, `ng g mimi login-01` (y `login-02`, `signup-01`, `otp-01`, `settings-01`) ya no crea `src/app/blocks/login-01/` con `Login01` y `mimi-login-01`, sino la página. `pricing-01` no cambia.
    - **B.11-i** Con `source(none)`, `init` y `ng g mimi` (al copiar una página) agregan el `@source` de la carpeta de páginas, como G1 con la de Blocks.
  - CLI: sin dependencias nuevas; `registry.json` (marca `kind`), `ui/schema.json` (`--name`), `ui/index.ts`, `utils/write-files.ts`, `utils/project.ts`, `utils/tailwind.ts`, `init/index.ts` y un módulo nuevo para las páginas.
  - Trampas conocidas: las bases y el manifiesto no pueden depender de la carpeta (B.11-f); la CLI de Angular pasa el Prettier del proyecto por lo que escribe (el estado `formatted` de `write-files.ts`); dos páginas con el mismo nombre por defecto en un comando (`ng g mimi login-01 login-02`); M2 también para `aliases.pages` y para `path` de `mimi.json`; con `source(none)`, sin `@source` la página queda sin estilos (G1); el resumen de M1 lee `mimi.json → blocks`, que ahora tiene `path` y `name`; Windows y rutas cortas en los escenarios con el `.tgz` (`docs/proceso/release.md`).
  - Criterios de hecho:
    1. `registry.json`: los seis Blocks con `kind` (cinco `page`, `pricing-01` `section`), comprobado por `registry.spec.ts`.
    2. `ng g mimi login-01` crea `<aliases.pages>/login/login.ts`, `login.html` y `login.routes.ts` (clase `LoginPage`, selector sin `mimi`), sus componentes y la línea para `app.routes.ts`; `pricing-01` sigue en `aliases.blocks` (pruebas de la CLI).
    3. `--name`, carpeta existente (error sin escribir nada), dos páginas con el mismo nombre, `aliases.pages` escrito si falta (pruebas).
    4. Seguimiento por nombre del registro: actualizar sin cambios, modificado sobre una versión anterior (bloqueado, con su aviso), `--overwrite`, M1 con otro nombre (pruebas).
    5. Compatibilidad: un proyecto con Blocks de la 0.4.0 se sigue actualizando donde está (prueba y escenario con la 0.4.0 real de npm).
    6. M2 para `aliases.pages` (pruebas).
    7. Sitio: página de Blocks, páginas de cada Block, Instalación (`mimi.json` con `aliases.blocks` y `aliases.pages`); README de la CLI; spec 4 y 5; CHANGELOG «Por publicar».
    8. Escenarios con el `.tgz`, fuera del repo y compilando: npm nuevo, pnpm nuevo, actualización desde la 0.4.0 de npm (con un Block modificado) y `source(none)`.
    9. `pnpm build`, `pnpm test`, `pnpm format:check` en verde; bundle del sitio antes y después.
    10. Lo que no se pudo ejecutar, a un revisor independiente.
